# NFR Requirements — unit-2-lambda-tagger

**Date**: 2026-03-25
**Stage**: NFR Requirements
**Traceability**: NFR-1, NFR-2, NFR-3, NFR-4, NFR-9, NFR-12 (requirements.md); US-6, US-13

Quantified non-functional requirements for the Auto-Tagger Lambda. IDs are
unit-local (`U2-NFR-n`); each cites its parent requirement where one exists.

## Performance and latency

### U2-NFR-1 — Tag latency (parent: NFR-9, US-13)
- **Typical**: `map-migrated` tag applied within **60–90 seconds** of resource
  creation (CloudTrail → EventBridge → SQS → first receive → tag).
- **Worst case**: **≤ 15 minutes** for slow-provisioning resources — exactly the
  SQS retry budget of 5 receives × 180 s visibility timeout = 900 s.
- **Coupled constant**: the 900 s budget is shared with unit-3's queue
  configuration and any verify-poll tooling. It changes both places or neither.

### U2-NFR-2 — Handler execution budget
- **Timeout**: 60 s per invocation — generous for a batch of tag API calls, small
  enough that a hung SDK call cannot eat a full visibility window.
- **Memory**: 256 MB — the handler is I/O-bound (JSON parsing + API calls); larger
  sizes buy nothing but cost. Revisit only with measured evidence.
- **Constraint**: timeout must remain **< 180 s visibility timeout** so a
  timed-out invocation's messages redeliver cleanly within budget.

### U2-NFR-3 — Throughput envelope
- Sized for enterprise resource-creation volume: tens to low hundreds of create
  events/hour/account, with migration-wave bursts absorbed by the queue.
- Default on-demand concurrency; **no provisioned concurrency, no always-on
  compute** (supports unit-3's NFR-8 cost ceiling).

## Reliability

### U2-NFR-4 — Idempotent tagging (parent: NFR-1) — hard
Re-applying `map-migrated=<same value>` to the same resource is a safe no-op.
This underwrites at-least-once delivery: redelivery, batch replay, and DLQ
re-drive are all correct without dedup state.

### U2-NFR-5 — Zero silent loss (parent: NFR-2, NFR-12)
Every eligible event terminates in exactly one of: **tag applied**, **ignorable
(logged with classification)**, or **DLQ + alarm**. No code path drops an event
without a classifiable log line. The failure budget is defined by this property,
not a percentage — a missed tag is permanently lost customer credit.

### U2-NFR-6 — Retry-budget correctness (parent: NFR-2, US-12)
- Transient failures (TRANSIENT_MARKER matches; **both** `ThrottledException` and
  `ThrottlingException`) return to the queue and get the full 5-receive budget.
- Partial batch response (`ReportBatchItemFailures`): only failed message IDs are
  reported; successful and ignorable records are consumed, so one slow record
  never burns its batch-mates' receives.

### U2-NFR-7 — Defensive parsing (parent: NFR-3) — hard
- All CloudTrail field access via `ci_get()` (case-insensitive).
- All event-supplied ARNs validated by `is_wellformed_arn()` before use.
- All external parsing (JSON, `strptime`, SSM reads) wrapped in narrow exception
  handling. **One malformed event must never crash the handler or its batch.**

## Security

### U2-NFR-8 — No outbound calls (parent: NFR-4) — hard
The handler makes **no network calls out of the customer's account**: no
telemetry, no update checks, no third-party endpoints. Only AWS service APIs in
the deployment partition. Verified by code review + the Build and Test gate; any
exception is a design change requiring explicit human sign-off.

### U2-NFR-9 — Least-privilege execution (parent: NFR-5)
The handler operates within a role granting only the tag actions the covered
services need (generated by unit-3 from unit-4's definitions, machine-checked).
The handler must not require, or be granted, any action outside that set. No
secrets, no credentials, no dynamic code loading.

## Configuration and observability

### U2-NFR-10 — Config caching (parent: FR-10, NFR-8)
SSM config read at cold start, cached module-level with a **5-minute TTL**;
last-known-good served through refresh failures; batch failed as transient if no
config has ever loaded. Bounds SSM call volume to ~1 per warm container per TTL.

### U2-NFR-11 — Observability (parent: NFR-12)
- Cold-start log line includes the template version.
- Every classification outcome (tagged / ignorable+reason / transient+marker /
  actionable+error) emits one structured, greppable log line.
- Log volume stays proportional to event volume (cost ceiling, NFR-8).

## Maintainability

### U2-NFR-12 — Standalone testability
The handler is one self-contained Python file, importable and unit-testable
without AWS, the browser plane, or the build. Every business rule (R-1..R-12) and
every extractor branch gets example-based tests plus golden captured CloudTrail
event fixtures (per the Property-Based Testing decision in requirements.md).

### U2-NFR-13 — Coverage parity (parent: FR-16)
Extractor branches map one-to-one to unit-4 service definitions; the automated
parity audit fails the build on a gap in either direction.
